# 图纸拓扑标识系统 2.0

这是一个面向工程图纸拓扑关系的管件识别、跨图匹配与标识系统。当前既保留焊口识别与智能编号能力，也在 EP3D 出图侧识别阀门、法兰和支架；设计图侧的既有识别规则保持不变。系统只把 `参考代码/PDF轴测图图元研究` 作为既有焊口算法来源，并保证该目录原样保留。

EP3D 管件识别优先读取方形标识框内的原生 PDF 文字，并沿框上引线确定管件位置：`V+数字` 表示阀门，`FL+数字` 表示法兰，`SP+数字` 表示支架。几何校验目前支持共顶点双三角阀门、带中心方向箭头的 Z 形阀门，以及法兰/支架使用的短平行线对。框、文字和引线是身份与位置的主证据，局部符号几何用于复核与细分；结果写入分析 JSON 的 `ep3dComponentInventory`，不会反向改变设计图候选。

## 架构

- 前端：Vue 3 + Vite
- 后端：Python 标准库 HTTP API
- PDF/图元：PyMuPDF
- 研究引擎：`pdf_vectors`、`dual_pdf_topology`、`idf_topology`

未采用 Django：当前程序是本机单用户工程工具，没有账号、权限、ORM 或后台管理需求，使用轻量 API 更容易部署和审计。

## 输入与流程

系统提供两种识别模式：

- 落图模式：识别未编号设计图。默认只接受主管上的黑色圆形闭合路径，通过几何圆度识别贝塞尔圆和高圆度密集折线路径；六边形等低边数近似圆及非圆形复合恢复只作为补充规则并默认关闭。完整圆形主体的物理中心必须落在工艺管线上；仅箭头尖端投影到主管不构成焊口。普通管件边界、共线管段间隙、横穿主管的短线和支管根部均不得仅凭拓扑或对照编号自动提升为焊口。`F`、`FS` 等前缀只作为对照身份，不表示 PDF 图元类型；落图模式依据实际描边数组排除视觉虚线焊口，不按编号前缀排除。参考数量只用于审计，不再用任意图元或未匹配边界补足数量；没有对照图时只保留完整圆形视觉签名，结果应重点人工核对。
- 对照模式：直接读取红框编号、红色引线及其焊点，保留所有可识别编号和视觉虚线焊口；编号身份与符号图元分类分别记录。
- 对照模式：使用研究包的红色人工编号逻辑，要求红色编号文字框及相连红色引线同时成立，并直接保留框内编号。

焊口基础形状、普通/X/方括号类型开关、尺寸、深色阈值、主管投影容差，以及红框开关、编号表达式和最低置信度均可在“焊口符号研究配置”中调整。

1. 必填：待标识 ISO PDF。
2. 可选参考输入（二选一）：
   - 已有焊口标识的对照 PDF：用于焊口身份和跨图拓扑匹配；
   - PCF：按标题栏 ISO 号选取对应文件，提取焊口节点、工程坐标、主构件、相邻管件类型及焊口连通关系，作为语义与一致性约束。
3. 图元研究直接生成候选并智能编号。
4. 编号完成后，在同一界面统一进行人工核对、排除误识别和修改编号。
5. 保存核对结果，导出 CSV 或带标识的 PDF。

仅上传待标识 PDF 时也能执行图元扫描，但没有独立参考拓扑，结果应重点人工核对。

## 启动

```powershell
cd frontend
npm install
npm run dev
```

另开一个终端：

```powershell
python backend/server.py
```

浏览器打开 `http://127.0.0.1:3004`。首次安装依赖后，也可以双击 `启动系统.bat`。

BAT 会保留一个可见的服务控制台，同时显示 Python 和 Vue 日志。请在使用期间保持该窗口开启；关闭窗口时，Windows 进程监护会同时结束前端、后端及其子进程。启动前还会检查 `3004`、`8768` 端口，避免误连到旧服务。

## 测试和构建

```powershell
python -m unittest discover -s backend/tests -v
cd frontend
npm test
npm run build
```

生产构建完成后，Python API 会直接托管 `frontend/dist`，可访问 `http://127.0.0.1:8768`。

## 数据

每次识别任务保存在 `data/jobs/<任务编号>`，包括原始上传、识别 JSON、页面预览和导出的标识 PDF。该目录默认不纳入版本控制。

- 服务启动时会把上次异常退出遗留的 `processing/cancelling` 任务标记为失败，避免任务永久卡住。
- 已完成、失败或取消的任务默认保留 90 天，超期后在服务启动时清理。
- 审计日志默认达到 10 MB 后轮转，保留 5 份历史文件。
- 浏览器草稿会在 IndexedDB 中保存图纸副本；工程文件敏感时，请使用系统设置中的草稿管理及时删除。
- `data/audit`、`data/jobs` 和 `backups` 均被 Git 忽略，避免把工程文件名、图纸和本地备份上传到代码仓库。

## PCF 解析器配置

系统自带内置 PCF 语义拓扑解析器。若需使用完整的 `idf-pipe-viewer` 解析器，可设置以下环境变量；系统不再依赖开发人员电脑的固定盘符：

```powershell
$env:PCF_REFERENCE_PARSER = 'D:\tools\idf-pipe-viewer\scripts\parse_pcf_to_json.py'
$env:IDF_REFERENCE_PARSER = 'D:\tools\idf-pipe-viewer\scripts\parse_idf_to_json.py'
```

也可以把解析器放在 `backend/vendor/idf-pipe-viewer/scripts`。解析器不可用时，结果 JSON 的 `pcf.degraded` 为 `true`，前端会显示醒目警告。

## 运行参数

以下环境变量可按部署需要调整：

| 变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `WELD_MARKER_MAX_BODY_MB` | 350 | 单个 JSON 请求体上限 |
| `WELD_MARKER_MAX_CONCURRENT_ANALYSES` | 2 | 同时执行的分析任务数 |
| `WELD_MARKER_MAX_PENDING_ANALYSES` | 4 | 执行中及排队任务总上限 |
| `WELD_MARKER_JOB_RETENTION_DAYS` | 90 | 终态任务保留天数 |
| `WELD_MARKER_AUDIT_MAX_MB` | 10 | 单份审计日志轮转阈值 |
| `WELD_MARKER_AUDIT_BACKUPS` | 5 | 审计历史文件数量 |

前端和 Python 依赖均使用精确版本；安装前请使用 Python 3.14 和 Node.js 22.13–24.x。

本次符号模式改造前的源码备份位于 `backups/焊口标识系统-符号模式改造前-20260901-102315.zip`。
