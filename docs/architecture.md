# 系统架构与工作机制

## 总体处理链路

```text
待标识 PDF
  -> 页面身份与标题栏提取
  -> PDF 文字、矢量路径和注释解析
  -> 焊口、阀门、法兰、支架候选生成
  -> 主管投影与图元门禁
  -> 页面关系与拓扑匹配
  -> 对照编号或 PCF 语义融合
  -> 编号与标识布局
  -> 人工核对、页面保存和导出
```

对照 PDF 先独立提取身份、编号框和引线，再通过页面关系和拓扑与设计图关联。PCF 提供语义及连接信息，但不会替代 PDF 页面上的实际候选证据。

## 页面身份与对照关系

系统优先从标题栏文字中提取标准化 ISO 号，必要时结合文件名、目录关系和页序信息生成候选。完全同号且页序一致时建立强关系；一张设计页明确引用多张后续图纸时可建立一对多关系。仅共享项目号、区域号或管线号不会自动视为同一张图。

页面身份和匹配候选写入结果 JSON，前端展示当前设计页对应的参考文件和页码。参考文件夹中的文件位置使用稳定槽位记录，避免文件缺失后索引错位。

## 焊口候选机制

- 默认识别主管上的黑色圆形闭合路径，包括贝塞尔圆和高圆度密集折线路径。
- 圆形主体的物理中心必须投影到工艺管线上；只有箭头尖端接触主管不视为焊口。
- 六边形等低边数近似圆及非圆形研究候选默认关闭。
- 管件边界、共线间隙、横穿主管短线和支管根部不能只凭拓扑或参考编号提升为焊口。
- 视觉虚线依据 PDF 实际描边数组判断，不根据编号前缀猜测。

## 管件与拓扑机制

阀门、法兰和支架综合使用标识框、文字、引线、材料表语义及局部几何。设计侧和参考侧候选保持隔离，避免参考对象数量直接改变设计候选数量。

建立候选后，系统在同一页面关系组内综合主管骨架、分支结构、焊口沿线次序、稳定管件地标、对象邻接和距离进行匹配。高可信参考身份优先用于编号，其余对象再按页内规则生成建议编号。

设计侧管件与焊口共同转换为带物理类型的拓扑节点，参考侧也转换为相同结构，完整调用焊口使用的 `match_weld_callout_topology` 流程，包括管线骨架绑定、局部端口签名、图邻接、沿线序列约束、显式缺口分配、唯一性门控与拓扑恢复。物理类型不一致是硬拒绝条件，禁止焊口、阀门、法兰和支架跨类型配对。管件不再采用焊口相对距离贪心匹配或独立支架顺序匹配；证据不足的单个对象也不会因两侧数量相等而自动配对。已有焊口结果不被管件上下文匹配覆盖，管件匹配的完整证据保存为 `componentMatchEvidence`，失败诊断保存为 `componentMatchDiagnostics`。

## 标识布局与编辑

后端在任务完成前对所有分析页执行初始标识避让。前端允许拖动标识框和引线端点，并可对当前页重新计算布局。焊口、阀门、法兰和支架分别维护外观配置。

布局障碍包含正文包围框、强管线、主图区域和普通矢量图线。普通图线由 PDF 直线及矩形边提取，经空间索引后对标识框执行精确相交检查；标识框压到尺寸线、引出线或设备轮廓属于硬冲突。候选位置先比较图线留白，再比较引线长度，并在管线法向之外搜索 24 个近邻方向。大尺寸水印文字仍显示，但不作为正文硬障碍。

核对锁失效时，页面只读提示以单行文字固定在工具栏下方的渲染区域右上角，不占外部布局空间，不随图纸缩放或平移，也不拦截画布操作。

编辑操作进入页面级历史快照，支持撤销和重做。复制粘贴会保留对象类型、编号、外观及引线相对位置，同时把新对象标记为人工对象并清除参考匹配身份。

人工新增编号与自动识别编号分开计算。每个页面、每种标识类型从任务设置的起始数字开始，只统计同类型且仍有效的人工新增对象作为后续偏移；自动识别对象不占用人工新增序列。任务级外观、编号和引线设置随草稿保存，登录用户的系统默认设置用于新任务，并可显式同步到当前任务。

## 页面保存与多人协作

- 页面进入时申请独占锁，并通过心跳续租。
- 默认锁租期为 180 秒，前端每 30 秒续租，续租成功后从当时重新延长 180 秒。
- 撤销与重做按任务、设计文件和页面隔离，切页保留该页自己的历史；每页最多保留 30 条，单个任务的全部页面合计最多保留 120 条撤销及重做快照，超限时淘汰最旧记录。只允许在持有当前页有效锁且不处于保存或同步过程时操作历史。历史恢复只修改编辑内容，不回退服务器核对版本及保存人、保存时间。
- 重新获锁后即使页面已缓存也会检查服务器版本；若服务器已有新版本，则更新未修改的缓存并清除该页旧历史。有未保存修改的页面不会被新版本静默覆盖。手动保存和切页保存共用同一个进行中的页面保存请求。
- 当前页修改进入浏览器草稿和页面 dirty 集合。
- 保存时提交页面数据、基础 revision、窗口标识和锁令牌。
- 手动保存会按页依次获取或复用锁并清空全部 dirty 页面，完成后只执行一次浏览器草稿事务；逐页切换仍只保存离开的页面。任一页面冲突或锁失败时停止后续提交并保留尚未保存的 dirty 页面。
- 服务端再次校验锁所有者和 revision 后，以原子方式更新任务结果。
- 切页时先乐观显示最后一次选择的目标页，但在事务完成前禁止编辑；原页保持页面锁并完成保存，保存失败则保留本地修改并回退原页。快速连续切页只激活最后一个目标页锁，过期请求已取得的锁会立即释放。保存并关闭仍先保存，再释放页面锁。

账号、会话、队列、页锁和普通任务的页面结果均存放在 SQLite WAL 数据库。Worker 每完成一页就将结果写入 `job_pages` 独立记录，最终布局优化后再批量发布完整页面版本；任务目录中的 `result.json` 只保存任务级状态与解析进度元数据。人工保存通过 `(job_id, page_number)` 和 `revision` 条件更新单页记录，并在同一事务中校验页面锁、写入审核事件，不再读取或重写整份任务 JSON。`jobs.summary_json` 只保留队列展示所需的轻量进度摘要，Worker 更新进度时同步写入；队列刷新完全从 SQLite 读取，不再逐个打开历史任务的 `result.json` 或 `job.json`。最近批次恢复所需的 `batch_id`、`batch_index` 和 `completed_at` 是 `jobs` 的独立列，服务端先在 SQLite 中筛出最新完整批次，再只读取该批次的页面结果；旧数据库升级时会从现有 `job.json` 和 `result.json` 修改时间一次性回填这些列。旧的 JSON-only 任务不会自动迁移，需要重新解析。

内置教程是只读的特殊资源，不属于普通任务：服务端直接读取 `backend/tutorial/result.json` 中已生成的预解析结果，不创建队列任务、不写入 `job_pages`，也不会因存储结构升级而重新解析。教程编辑只写入当前浏览器草稿；服务端不提供教程页面保存接口。只有识别规则本身变更且需要更新示例内容时，才应显式重新生成教程预解析文件。

## 浏览器草稿与恢复

IndexedDB 使用分层结构：

- `draftMetadata`：名称、更新时间、页数等摘要；
- `workspaceManifests`：工作区结构和文件引用；
- `workspacePages`：按工程和页码拆分的页面结果；
- `workspaceFiles`：主图、参考图和 PCF Blob。

文件按内容指纹去重，工作区只保存引用。草稿通过跨仓库事务提交。浏览器草稿以容灾为目标，不会因为后端已有同名文件而省略文件副本。

恢复浏览器草稿或 PDF 内嵌工作区前，前端读取对应服务端页面并比较候选标识内容及页面 revision。内容相同的页面保持 clean；revision 未变化的本地差异直接标记 dirty；两侧均变化的页面进入人工决策。用户确认覆盖后，前端在保留本地候选内容的同时采用服务端最新 revision，逐页获取锁并提交，避免普通页面同步在恢复期间覆盖本地内容。恢复期间 `hydratingWorkspace` 阻止自动获锁 watcher 介入，恢复完成后再显式激活当前页锁。

删除草稿或读取草稿列表时，前端会从全部剩余 manifest 汇总 `storedFileKey`，只回收 `workspaceFiles` 中没有任何引用的 Blob。该标记清扫机制允许多个草稿安全共享同一份 PDF/PCF，同时清理旧版本遗留的孤儿文件。

## 大文件与懒加载

- 首次恢复只返回当前页完整数据和其他页面轻量信息。
- 页面详情在翻页时加载。
- 参考 PDF 按当前页面关系加载，已打开文档使用有限缓存。
- 教程和普通任务在前端共用按页加载方式；普通任务从 `job_pages` 读取，教程从内置只读预解析文件读取。
- 页面位图缓存根据设备能力和性能设置控制。
- 草稿列表只读取摘要，恢复时先加载当前页。

这些策略降低首次进入工作区时的 JSON 反序列化、响应式对象创建、PDF Blob 读取和位图渲染压力。

## AI 助手与文档检索

AI 对话采用受控代理链路：`AssistantPanel.vue` 通过 `api.chatStream` 调用受认证的 `/api/ai/chat/stream`，`ai_assistant.py` 负责配置、输入验证、系统提示词和界面上下文，`assistant_agent.py` 解析 DeepSeek 流式内容和函数工具调用，`assistant_tools.py` 校验工具参数，`document_knowledge.py` 只检索知识清单登记的系统 Markdown。

模型不能访问文件路径。它只能调用 `search_system_documents(query, limit)` 或 `read_document_section(document_id, section_id)`；后端把真实检索结果作为 `role: tool` 消息返回。工具调用最多三轮，最终回答继续以 SSE 增量传输。思考模式的 `reasoning_content` 仅在模型多轮协议内部回传，不进入浏览器。

知识库由 `docs/assistant-knowledge.json` 显式登记。文档按标题和段落分块，使用 Unicode 规范化、英文词项、中文字符及二元片段进行确定性排序。索引缓存依据清单摘要、文件大小和修改时间自动失效。回答来源仅包含稳定文档 ID、相对路径、章节和行号。

```text
用户问题 -> DeepSeek 判断是否查资料 -> 受控文档工具 -> 本地 Markdown 片段
        -> DeepSeek 生成有依据的回答 -> status/source/delta SSE -> AI 面板
```

当前检索范围只包含项目系统文档，不包含任务 PDF、PCF、结果 JSON、SQLite、审计日志或 `.env`。检索片段会发送给 DeepSeek，因此未来开放工程资料前必须增加授权、任务归属和脱敏边界。详细协议见 [AI 助手与本地文档检索](ai-assistant.md)。

## 路由与后台管理

前端使用 Vue Router 的 HTML5 History 模式，`/login` 为登录页，`/main` 为图纸工作台，`/` 和未知前端地址先跳转到工作台，`/admin`、`/admin/users` 和 `/admin/database` 为后台视图。未登录访问工作台或后台时会携带原目标地址跳转到登录页；Python 静态文件入口对未知前端路径回退到 `index.html`，因此直接刷新这些前端地址仍可恢复路由。

`users.is_admin` 是后台授权依据，现有数据库启动时自动增加该列，内置 `admin` 账号会被提升为管理员。每个账号在 `sessions.user_id` 上具有唯一会话，新登录原子替换旧登录凭证并释放该账号已有的页面锁；旧客户端无法继续调用业务接口或续租、保存页面。所有 `/api/admin/*` 接口同时要求有效会话和管理员身份。`AdminStore` 只执行固定只读查询，用户响应排除密码哈希与盐，数据库响应只包含批准表的行数和 SQLite 元数据。DeepSeek 余额由后端携带密钥请求官方 `/user/balance`，浏览器只接收币种与余额，不接收密钥。

## 技术组成

- 前端：Vue 3、Vuetify、Vite、PDF.js、IndexedDB。
- 后端：Python 标准库 HTTP API、PyMuPDF。
- 队列与协作状态：SQLite WAL。
- 研究模块：`pdf_vectors`、`dual_pdf_topology`、`idf_topology`。
- AI 模块：`ai_assistant`、`assistant_agent`、`assistant_tools`、`document_knowledge`。
- 部署形态：单 API、多 Worker、共享任务数据卷。
